# AGENTS.md

This file provides guidance to AI Agents when working with code in this repository.

## Commands

Package manager is **pnpm** (version pinned in `package.json`). Node version is pinned in `.node-version`.

- `pnpm dev` — Vite dev server on port **8080**
- `pnpm build` — production build into `.output/`
- `pnpm preview` — preview the production build locally
- `pnpm test` — run Vitest (see "Testing" below for project split)
- `pnpm lint` — Oxlint with type-aware rules (`oxlint --type-aware`, powered by `oxlint-tsgolint`); config in `.oxlintrc.json`
- `pnpm format` / `pnpm format:check` — Oxfmt (Prettier-compatible output, with built-in import sorting and Tailwind class sorting); config in `.oxfmtrc.json`
- `pnpm typecheck` — runs `cf-typegen` first, then `tsc --noEmit` (TypeScript 7, the native compiler) for both app and `tests/tsconfig.json`
- `pnpm cf-typegen` — builds, then regenerates `worker-configuration.d.ts` from `.output/server/wrangler.json` (not from `wrangler.jsonc` directly)
- `pnpm check` — the CI gate: `format:check && lint && typecheck && deploy:dry-run`
- `pnpm deploy` / `pnpm deploy:dry-run` — publishes via `wrangler --cwd .output`; deploy-dry-run is part of `check` to catch Worker-level misconfig before merge

Run a single test file: `pnpm test <path>` (e.g. `pnpm test tests/features/prompt-library/persistence/remote/remote-prompt-library-persistence.server.test.ts`). Filter by name with `-t "<pattern>"`.

Apply D1 migrations locally: `pnpx wrangler d1 migrations apply promptrc --local`.

## Architecture

### Local-first storage with a unified client

The prompt library has two backends behind one interface:

- `src/features/prompt-library/persistence/prompt-library-storage.ts` — the `PromptLibraryStorage` discriminated union (`mode: 'local' | 'remote'`)
- `persistence/local-prompt-library-storage.ts` — `localStorage` adapter (anonymous users)
- `persistence/remote-prompt-library-storage.ts` — Cloudflare D1 via TanStack server functions (signed-in users)
- `sync/prompt-library-client.ts` — `createPromptLibraryClient` builds a single `PromptLibraryClient` on top of either storage; components never branch on auth/mode

`PromptLibraryProvider` (`components/prompt-library-provider.tsx`) wires Clerk auth → `usePromptLibraryStorage` (picks adapter) → `createPromptLibraryClient` → Zustand store. Hydration happens in `usePromptLibraryHydration`: local mode subscribes to the store to persist every change; remote mode does not (writes go through server funcs explicitly).

**Implication:** don't add mode checks in components/hooks. If a behavior differs between local and remote, it belongs inside the client/storage layer.

### Server functions + Cloudflare bindings

`src/features/prompt-library/server/prompt-library-functions.ts` defines TanStack Start `createServerFn` endpoints. Important patterns:

- The D1 binding is accessed via `const { env } = await import('cloudflare:workers')` inside `getDatabase()` — **not** a top-level import. Vite externalizes `cloudflare:workers` (see `vite.config.ts` `build.rollupOptions.external`), so a static import would break the client bundle.
- Every handler calls `requireUserId()` (Clerk `auth()`) and scopes queries by `ext_user_id`. New endpoints must follow this pattern; there is no separate authorization layer.
- Exported pure DB helpers (`listPromptsForUser`, `upsertPromptForUser`, etc.) exist so tests can call them with a direct `D1Database` handle without going through the serverfn wrapper.
- D1 row encoding/decoding and remote write transitions live in `persistence/`; the `server/` folder should stay focused on TanStack server-function wrappers and Cloudflare binding access.

### State

Zustand **vanilla** store (`store/prompt-library-store.ts`) — the React tree consumes it through `useStore(store, selector)` exposed by `PromptLibraryProvider`. The store holds prompts, workspace state (query/selection/composer), and sync state together; mutations go through the `actions` slot (never direct `set` from outside).

### Routing

File-based routes in `src/routes/`. The generated `routeTree.gen.ts` is `.gitignored` in effect (regenerated by the TanStack router plugin during `dev`/`build`). `sign-in.$.tsx` / `sign-up.$.tsx` are catch-all Clerk routes.

### Interface

The library screen (`components/prompt-library-app.tsx`) is three panes: `library-sidebar.tsx` (filters by kind, category, tag, plus sync/theme/account), `prompt-list.tsx` (query, sort, catalog numbers), and either `prompt-reader.tsx` or `prompt-editor.tsx`. Overlays are `quick-capture-dialog.tsx` (`c`), `command-palette.tsx` (`⌘K`, cmdk), and `keyboard-sheet.tsx` (`?`). On narrow screens one pane shows at a time and the sidebar becomes a drawer.

- **Kinds** (`prompt`, `fragment`, `sequence`, `benchmark`) are one record shape; see `docs/adr/0004-prompt-kinds-share-one-record.md`. Kind metadata and copy live in `model/prompt-kinds.ts`; kind marks (¶ “ § ※) in `components/kind-mark.tsx`.
- **Template variables** (`{{name}}`, `{{name | fallback}}`) are parsed in `model/prompt-templates.ts`, turned into inline inputs by `rendering/remark-prompt-variables.ts` + `rendering/prompt-variable-slot.tsx`, and substituted on copy by `model/prompt-copy.ts`. Typed values are remembered per Prompt in `localStorage` (`hooks/use-prompt-variable-values.ts`).
- **Theme**: tokens are CSS variables in `src/global-styles/tailwind.css` (shadcn-compatible names, so Base UI primitives and Clerk's shadcn theme follow light/dark). `src/lib/theme.ts` owns the light/dark/system preference and the inline no-flash script in `__root.tsx`. Don't hard-code colours in components — use the `paper`/`ink`/`rule`/`vermilion`/`kind-*`/`verdict-*` utilities.
- The React Compiler (native oxc port, via `@vitejs/plugin-react`) memoizes components, so don't add `useMemo`/`useCallback` for render performance alone.

### Feature layout convention

Colocate under `src/features/<feature>/`: `components/`, `hooks/`, `model/` (Prompt records, defaults, normalization), `selectors/` (derived state for UI/workflows), `commands/` (shared command metadata and executors), `rendering/` (display formatting and body tokenization), `persistence/` (storage adapters, D1 mapping, remote transitions), `sync/` (client/session/hydration orchestration), `server/` (serverfn wrappers), `store/` (Zustand), `types.ts`. New features should follow this shape when the same concerns exist.

Tests should mirror the feature folders under `tests/features/<feature>/`. Use the `.server.test.ts` suffix for tests that need the Cloudflare workers pool, including D1 persistence and server-function tests.

### Path alias

`@/*` → `src/*` (tsconfig + vitest alias). Use the alias in imports; Oxfmt's import sorting groups `@/` imports separately from third-party and relative imports — don't hand-reorder.

## Testing

`vitest.config.ts` defines **two projects** in one run:

- `browser-unit` — `jsdom`, includes `tests/**/*.test.{ts,tsx}` but **excludes** `tests/**/*.server.test.{ts,tsx}`
- `cloudflare-server` — `@cloudflare/vitest-plugin` Miniflare, includes `tests/**/*.server.test.{ts,tsx}`, runs `tests/setup-cloudflare.ts` which re-applies D1 migrations and truncates `prompts` before each test

Vitest is on v5. `@cloudflare/vitest-plugin@1.3.6` only declares support for Vitest 4, so `patches/@cloudflare__vitest-plugin@1.3.6.patch` backports the Vitest 5 changes from cloudflare/workers-sdk#15500 (new module registry, `weak_ref`, `node:process` fallback, coverage loopback). `pnpm-workspace.yaml` allows the peer mismatch. Remove both once an upstream release supports Vitest 5.

**Naming matters:** D1 and server-function tests must use the `.server.test.ts` suffix so they hit the workers pool (and get the D1 binding). Put browser/unit tests in the mirrored feature folder without that suffix, or they'll run in the wrong environment.

## Version pins worth knowing

- `nitro` is pinned to `3.0.260610-beta`: in `3.0.260903-beta` the workerd dev runner inlines CommonJS dependencies (React) and `pnpm dev` fails with `module is not defined`.
- `miniflare@^4` is a direct dev dependency because Wrangler and `@cloudflare/vitest-plugin` now ship miniflare 5 (alpha), while Nitro's `env-runner` needs v4.
- `vite.config.ts` marks `cloudflare:workers` external for the dependency optimizer too; otherwise the dependency scan aborts on the dynamic import.

## Deployment

Target: Cloudflare Workers with a D1 binding named `DB` (see `wrangler.jsonc`). `nitro.config.ts` sets the Nitro preset to Cloudflare; retargeting elsewhere is a preset change. `pnpm build` outputs the Worker bundle + `.output/server/wrangler.json`, and `pnpm deploy` runs wrangler against that output directory — never the repo root.

Production routes (`promptrc.app`, `www.promptrc.app`) and the D1 database id are pinned in `wrangler.jsonc`. `wrangler deploy` (and the Deploy workflow) does **not** apply D1 migrations — run `pnpx wrangler d1 migrations apply promptrc --remote` before shipping code that depends on a new migration. Fork-to-deploy requires editing those and setting `CLERK_SECRET_KEY` as a Worker secret.

## Environment

- `VITE_CLERK_PUBLISHABLE_KEY` — client, required
- `CLERK_SECRET_KEY` — server/worker only, required
- `VITE_SITE_URL` — optional canonical origin for SEO; defaults handled by `src/lib/site-config.ts`

Only `VITE_*` vars reach the client bundle.

## Conventions

- Oxfmt: **no semicolons**, single quotes, trailing commas, imports sorted into third-party / `@/` / relative groups. Don't fight it.
- Oxlint: `array-simple` for array types; inline type specifiers (`import { type Foo }`) are enforced; React Compiler rules (`react/refs`, `react/set-state-in-effect`, `react/purity`, `react/static-components`) and jsx-a11y are on. Prefer native elements (`<input type="radio">` via `components/ui/choice.tsx`, `<button>`) over ARIA roles.
- Copy in the UI is calm and sentence-case. Notifications read like `Copied “Title”`, not terminal output.
- Adding a shadcn component: `npx shadcn@latest add <name>` (registry config in `components.json`).
